EDA Interview Playbook Python · Data
1
Understand the shape always first
Before touching anything — know how big the data is, what columns exist, what types they are.
df.shape # rows × columns df.dtypes # data type of each column df.head() # see what the data actually looks like
what to look for
Unexpected dtypes — e.g. a date column showing as object means it's stored as text and needs converting.
2
Check missing values
Find which columns have nulls, how many, and decide how to handle them.
df.isnull().sum() (df.isnull().mean() * 100).round(2) # as %
decision rule
<5% → impute (median for skewed, mean for normal)  |  >30% → consider dropping column  |  Always ask why it's missing.
interview tip
Don't just say "I'll fill it with the mean." Say why — income is right-skewed, so median is safer than mean.
3
Check uniqueness & primary key
Confirm no duplicate rows exist, and identify which column is the unique identifier.
df.duplicated().sum() # duplicate rows df.nunique().sort_values() # unique count per column
reading the output
nunique = 1 → useless column (zero variance)  |  nunique = 2–20 → likely categorical  |  nunique = total rows → primary key candidate
4
Inspect data quality
Categorical columns: look for invalid/typo values. Numeric columns: look for outliers.
# Categorical — check all unique values for col in df.select_dtypes(include='object').columns: print(df[col].value_counts(), '\n') # Numeric — distribution summary df.describe() # Numeric — IQR method to flag outliers Q1 = df['Income'].quantile(0.25) Q3 = df['Income'].quantile(0.75) IQR = Q3 - Q1 df[df['Income'] > Q3 + 1.5 * IQR]
interview tip
The IQR method is the standard answer for "how do you detect outliers?" Always have this ready.
5
Identify data gaps no code needed
Think like a business analyst — what questions can this data NOT answer? What's missing that would make the analysis stronger?
examples for this dataset
No geography → can't analyse regional behaviour
No transaction detail → only 2-year spending totals, can't see seasonality
No campaign content → know who accepted, not what the offer was
interview tip
This step separates analysts from coders. Most candidates skip it. Doing it well is a big differentiator.
Copy this into your notebook. Run top to bottom. Every line has a purpose.
### STEP 1 — Shape & types print(df.shape) print(df.dtypes) df.head() ### STEP 2 — Missing values missing = df.isnull().sum() pct = (df.isnull().mean() * 100).round(2) pd.DataFrame({'count': missing, 'pct': pct})[missing > 0] ### STEP 3 — Uniqueness & primary key print('Duplicate rows:', df.duplicated().sum()) df.nunique().sort_values() ### STEP 4a — Categorical columns: value counts for col in df.select_dtypes(include='object').columns: print(f'\n--- {col} ---') print(df[col].value_counts()) ### STEP 4b — Numeric columns: distribution df.describe().round(1) ### STEP 4c — Outliers (IQR method) for col in df.select_dtypes(include='number').columns: Q1 = df[col].quantile(0.25) Q3 = df[col].quantile(0.75) IQR = Q3 - Q1 n_out = (df[col] > Q3 + 1.5 * IQR).sum() if n_out > 0: print(f'{col}: {n_out} outliers') ### STEP 5 — Write your conclusions (Markdown cell) # Shape, missing, primary key, dirty data, gaps
key habit
Steps 4a and 4b use select_dtypes() — this automatically finds the right columns. Never hardcode column names you could infer from the data type.
Opening line — say this before touching the keyboard
"I'll follow a structured EDA framework: first understand the shape and data types, then check for missing values, then uniqueness and primary keys, then data quality issues like dirty values and outliers, and finally identify what's missing from the dataset that would strengthen the analysis."
When you find something — how to frame it
You found 24 missing values in Income
weak answer
"Income has 24 nulls. I'll fill them with the mean."
strong answer
"Income has 24 missing values — about 1%. Before imputing, I'd check whether the missingness correlates with other variables. Since income distributions are typically right-skewed, I'd use the median rather than the mean to avoid being pulled by outliers."
You found 'YOLO' and 'Absurd' in Marital_Status
weak answer
"There are some weird values I'll clean up."
strong answer
"Marital_Status contains 'YOLO' and 'Absurd' — clearly data entry errors. Together they're only 7 rows, or 0.3% of the dataset, so dropping them has negligible impact. Alternatively, they could be merged into 'Single' since they likely represent single individuals."
Closing summary — end every EDA with this
"To summarise: the dataset has [X] rows and [Y] columns, [ID] as the primary key, and no duplicate rows. The main issues are [list 2–3 findings]. Before modelling, I would [actions]. One limitation of this dataset is that it lacks [gap], which would prevent us from [business question it blocks]."
the golden rule
Every finding needs three parts: what you found → why it matters → what you'd do about it. One sentence each is enough.
Use this as a mental checklist during the interview. Tick each one off before moving to the next step.
Step 1 — Shape
  • Stated the number of rows and columns out loud
  • Checked dtypes — flagged any that look wrong (e.g. date stored as object)
  • Looked at head() to understand what a row actually represents
Step 2 — Missing values
  • Identified which columns have nulls and what percentage
  • Discussed why they might be missing (not just that they exist)
  • Proposed a handling strategy with justification
Step 3 — Uniqueness
  • Confirmed zero duplicate rows
  • Identified the primary key
  • Used nunique() to classify columns (constant / categorical / continuous / ID)
Step 4 — Data quality
  • Ran value_counts() on all categorical columns
  • Spotted invalid category values (typos, junk entries)
  • Ran describe() and looked at min / max carefully
  • Applied IQR method to flag numeric outliers
  • Identified zero-variance columns (nunique = 1) to drop
Step 5 — Data gaps
  • Named at least 2 pieces of information the dataset doesn't have
  • Explained what business question each gap prevents you from answering
Delivery
  • Stated your framework out loud before starting
  • Every finding was followed by "why it matters" and "what I'd do"
  • Closed with a 3-sentence summary
